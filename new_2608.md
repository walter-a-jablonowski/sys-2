### UI

```
-------------------------------------------------------
| NAME    [edit] | NAME_2                |   [AI] ... |  <-- app header
-------------------------------------------------------
| TABS       [+] |                       |        + v |  <-- Second (small) AI header (AI sidebar only)
| TOOLS          |                       |------------|
|                | EDIT                  |            |
|                |                       |            |
| LIST           |                       | AI sidebar |
|                |                       |            |
|                |                       |            |
|                |                       |            |
|                |                       |            |
|                |                       |------------|
|                |                       | [     ][ ] |  <-- Input and send button
|----------------|-----------------------|------------|
| FOO            |                       |            |  <-- small fooder area
-------------------------------------------------------
```

3 col content area layout:

- "App header" and "fooder area"
  - No typical app header instead we only use the same design for the whole lines
  - in principle the layout use a 3 column layout
  - Commonly used things in app header line
    - [AI] = unfold AI sidebar
    - ... = dropdown menu
      - entry specific entries
      - devider
      - commonly used entries
  - The remaining elements are column specific

- Left column (where LIST is): List of rendered entries
  - Layout
    - in app header line: Name of the currenly visible entry form the hierarchie (edit button rifht aligned)
    - TABS: "Entries" (sub entries), "Participants", "Resources"
      - aligned to the right: Add dropdown for new entry
    - TOOLS: Visible for tab "Entries" only: toolbar e.g. filters for the list
    - List:
      - list entries
        - "cards" with rendered layout per type (no gap/margin) 
        - CRUD functions like delete
      - end of list: load more functionallity (button)
    - small fooder area: we can put some buttons or states there (or leave empty for now)
  - navigation
    - second level directly unfoldable
    - third and deeper levels in herarchie: navigate to sub level on click or touch
- EDIT: rendered detail editor per type
  - in app header: NAME_2 is name of currently selected entry ("Current" in case "[edit]" was clicked)
  - Edit content area may also support tabs (depends on type rendered)
  - small fooder area: content depends on type
- AI sidebar: UI dummy for now, implementation later, unfoldable witn [AI]
  - second (small) header below app header (plus = new session, "v" = unfold session list)
  - Input and send area

Find a good looking width for each of the 3 sidebars. First columns can't be too narrow in case we have many attributes in rendered list entries we must be able to show it there.
